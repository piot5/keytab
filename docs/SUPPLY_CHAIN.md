# Supply Chain & Workflow Pinning

Two independent safeguards: **Gradle dependencies** are verified by checksum, and **GitHub Actions** are pinned to immutable commit SHAs. No tag or branch of a foreign action is ever executed.

## 1. Gradle Dependency Verification

Enabled in `gradle/verification-metadata.xml` (~3,300 lines, generated by Gradle). It contains SHA-256/PGP entries for all direct and transitive compile/runtime dependencies, the Gradle distribution itself, and the Android Lint toolchain.

Adding a new dependency without extending the metadata ⇒ `./gradlew --write-verification-metadata` fails and every CI job with resolution is blocked. That is intentional: the change must be visible.

```bash
# Check (standard in every build)
sh gradlew :app:dependencies

# Extend metadata consciously — review duty, separate commit
sh gradlew --write-verification-metadata sha256
```

**Rule:** `--write-verification-metadata` is never used in the same commit as a functional change. Separate commit, visible in the diff.

## 2. Pinned GitHub Actions

All `uses:` references point to 40-hex-digit commit SHAs. Current state:

| Action | Commit SHA | Used in |
|---|---|---|
| `actions/checkout` | `fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09` | ci.yml, release.yml |
| `actions/setup-java` | `b6effb05e454b25005698d916606bdc6ffcbf961` | ci.yml, release.yml |
| `actions/upload-artifact` | `b7c566a772e6b6bfb58ed0dc250532a479d7789f` | ci.yml |

Every occurrence of a multi-used action (`checkout` 5×, `setup-java` 4×, `upload-artifact` 4×) must carry the same SHA. A mixed pin state is an error, not a detail.

`reactivecircus/android-emulator-runner` (SHA `324029e2…`) is **no longer used**: the `instrumented` CI job was removed on 2026-10-29 (the API-34 emulator never brought the IME window up in time — details in `.github/workflows/ci.yml`). The instrumented suite runs on a real device via `scripts/test_on_device.sh`.

## 3. Updating a pin

A SHA pin without a documented update path is a maintenance risk. Fixed process:

1. **Find the current version.** `gh api repos/<owner>/<action>/tags` or check the action's releases. Only official releases, no nightly/pre-release tags unless necessary.
2. **Resolve tag → SHA.** `git ls-remote https://github.com/<owner>/<action> refs/tags/<tag>` — for annotated tags use the dereferenced `^{}` object.
3. **Replace all occurrences.** Same action appears multiple times — `grep -n` over both workflows and replace every occurrence, not just the first.
4. **Verify locally.** `grep -nE 'uses: [^@]+@' .github/workflows/*.yml` — no `@v` / `@main` allowed.
5. **Commit.** Own commit, message `ci: actions/<name> pinned to <tag> (<short-sha>)`. No mix with code changes — the pin bump must be reviewable in isolation.

## What explicitly does not happen

- **No Dependabot for Actions.** An auto-bump would silently erode the pin discipline.
- **No tag pins, not even `v4`.** A tag is a moving reference; that eliminates the value of pinning.
- **No `pull_request_target` / fork code in the release workflow.**
